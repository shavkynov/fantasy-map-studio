# Тектоническая история мира (план, 2026-11-18)

Решения владельца: (1) считать для геоида, сопоставимого с Землёй (радиус в границах земной группы); плоская карта допустима только для отработки механики; (2) возраст мира = возраст Земли по геологическим процессам и ископаемым (~4,5 млрд лет); (3) шаги генерации не показывать, в конце — ползунок времени (промотка дрейфа вперёд/назад).

## Модель (минимально достаточная)
- Сфера, растр 360×180 (до 720×360), долгота периодична. Мир = поле континентальной коры `C` (0..1.5, океан = 0 по умолчанию).
- История = ~8–10 эпох по ~450 млн лет. Эпоха: (а) трещины делят текущую континентальную массу на 3–10 плит (Вороной от случайных точек внутри коры, границы искажены шумом); (б) у каждой плиты полюс вращения (случайная ось) и угловая скорость; (в) аналитический дрейф: положение плиты в момент t = поворот вокруг оси на угол ω·t, без накопления размытия; (г) ~16 подшагов для поиска перекрытий: перекрытие двух плит = столкновение (кора складывается, копится «горообразование» эпохи); (д) в конце эпохи растр пересэмплируется один раз, плиты склеиваются в одно поле, следующая эпоха режет заново.
- Скорости: базовый масштаб = f(радиус, «тепловая активность» — одно число); малые плиты быстрее. Угол = v·t / R.
- Горообразование эпох затухает экспоненциально с возрастом (эрозия): последняя эпоха → `young`, более ранние → `old`. Это те же поля, что уже читает остальной конвейер.
- Длина записи истории: плиты, оси, скорости, кора каждой эпохи — килобайты. Ползунок времени = пересчёт положения по формуле при другом t (без повторного прогона).
- Побочный выход: возраст коры и возраст/тип складчатости в каждой клетке → ископаемые (щиты/кратоны — руды железа и золота; орогены — цветные металлы; осадочные бассейны — уголь/нефть; рифты — соли). Не в первом проходе.

## Что заменяет
`terrain-edit-spherical-base.js` (статическая раскладка материков + кинематика границ по `omega`) в качестве источника суши/плит; в основном мире — `makePlates/pairConv/separateContinents/analyzeBoundaries/orogeny/epochs`. Число материков становится результатом, не параметром.

## Риски
Берега-«пазлы» от трещин (лечить шумом на трещинах и существующей регуляризацией); подбор диапазона скоростей/длины эпох, чтобы не получать ни «кашу», ни «одни острова»; площадь коры не сохраняется при столкновении (компенсирует уровень моря по `landRatio`); `golden`/метрики формы переписываются целиком.

## Порядок
1) прототип `src/sphere-tectonic-history.js` + тест инвариантов (детерминизм, площадь, число масс, ось поворота, обратимость времени); 2) сравнение силуэтов с текущим генератором (доли, число и размеры масс, неразличимость от Земли по статистике); 3) подключение в `spherical-bridge`; 4) ползунок времени; 5) ископаемые.

## Дополнение 2026-11-18: взаимозависимости (требование «максимальный реализм»)
Принцип: реализм = верные причинные связи, а не пошаговая физика. Каждая связь — отдельная, минимально достаточная модель на эпоху (не по годам), со своим тестом и выключателем. Влияющее на силуэт и рельеф снимка включаем; не влияющее — нет.

| Связь | Что от чего зависит | Уровень |
|---|---|---|
| Изостазия | мощность коры → высота суши и глубина дна (толстая кора поднята, тонкая и старая океаническая остывает и тонет) | A |
| Эрозия и осадки | горы стираются со временем, материал оседает на шельфах, дельтах, в бассейнах; шельф шире у пассивных окраин | A |
| Масса воды | объём воды = параметр планеты; уровень моря = решение «вода заполняет котловины» (гипсометрия). `landRatio` перестаёт быть входом и становится результатом | A |
| Объём океанических котловин | быстрые срединные хребты (молодая горячая кора) вытесняют воду → уровень моря выше; старая кора — ниже | A |
| Ледниковые циклы | полярная суша + похолодание (орбита, углекислота, положение материков) → ледяные щиты: вода уходит в лёд → уровень моря падает до ~120 м; ледник вытачивает фьорды, озёра, моренные гряды; после таяния изостатический подъём | B |
| Мантийные плюмы | горячие точки: цепочки островов и подводных гор вдоль дрейфа плиты; крупные магматические провинции; плюм под континентом → рифт (раскол) | B |
| Вулканические дуги | субдукция у края континента → береговой хребет и островные дуги | B |
| Цикл суперконтинента | собранная суша изолирует мантию → нагрев → раскол | B |
| Выветривание и климат | климат ← положение материков, горы ← осадки; обратная связь с ледниками | B |
| Удары астероидов | кратеры, события (редактор катастроф уже есть) | C |
| Карбонатные платформы и рифы | тёплые мелководья на шельфе | C |

Уровень A входит в первый проход. B — вторым. C — по необходимости для снимка.

### Предел достоверности (честно)
Реальной «правильной» истории для вымышленной планеты нет: проверять можно только внутреннюю согласованность (баланс воды и льда, сохранение объёма коры при столкновении, уровень моря = объём воды / котловины) и статистическое сходство с Землёй (доли суши, распределение размеров масс, высоты, ширина шельфа, число и возраст орогенов). Точность каждой связи — порядок величины; не «моделирование Земли».

## Статус прототипа (2026-11-18): `src/sphere-tectonic-history.js`, тест `tools/sphere-tectonic-history-test.cjs` (11 проверок, в `npm run check`)
Сделано (уровень A, частично): суперматерик (облако точек равной площади), эпохи 150 млн лет × 30, трещины на 4–8 плит, твёрдое вращение плит по сфере, сварка при столкновении, растекание сверхмощной коры (T>60 км), изостазия, эрозия одним проходом после истории (снесённое оседает шельфом ≤22 км, излишек считается потерей), уровень моря из объёма воды (доля суши — результат: ≈25% при Земле-подобной воде 2,62 км).
Замеры (360×180, 3 seed): ≈4,5–5 с на мир; суша 24,8–26,1%; осадок теряется ≈16–18% объёма; сварок 70–99 за историю.
Не сделано / слабые места: гор мало (нет субдукции и дуг; пояса от столкновений живут только последние ~150 млн лет); внутри материков почти плоско (рельеф даст последующий слой шума/эрозии); океанское дно без возраста и срединных хребтов; нет ледников, плюмов, ископаемых; «ползунка» нет (есть `stopAtMyr`/`snapshotEveryMyr`); скорость 5 с избыточна для интерфейса (Rust/оптимизация); не подключено к `spherical-bridge` и к редактору.

## Сравнение с World Orogen (2026-11-18)
Источник: github.com/raguilar011095/planet_heightmap_generation («World Orogen», режим Evolution; ссылка из README dunkean/magna-urbis — сам magna-urbis делает города/ландшафт, тектоники в нём нет). Лицензия GPL v3: код не копировать и не переносить; брать только идеи и методику (она — из руководств Worldbuilding Pasta и статей, не из кода). Читал документацию и дизайн-документ `plans/V2_TECTONIC_HISTORY_DESIGN.md`, код не запускал.
Совпадает с нашим: суперматерик → раскол → дрейф → столкновения и склейки; кора в системе плиты (движение точное); сварка плит при столкновении; уровень моря из доли суши; ползунок времени по готовой истории; ископаемые от истории; ледниковый период.
Чем лучше нашего: (1) движение плит из сил, а не случайные оси: тянущая сила погружающейся плиты главная, хребты пассивны; скорости в диапазонах см/год по типу границы; (2) субдукция: океан уходит под континент, у края — береговой хребет или островная дуга; континентальная кора не тонет; (3) океаническая кора рождается на хребтах симметрично и стареет (~250 млн лет), старая тонет раньше; (4) трещины идут по слабым местам: ищут путь от плюмов, обходят кратоны, любят старые швы; третья ветвь — несостоявшийся рифт (будущая речная долина); (5) горячие точки в системе мантии оставляют цепочки с возрастом; (6) симуляция только записывает события (тип орогении, интенсивность, возраст), а рельеф «интерпретирует» их отдельно; (7) история 300–1500 млн лет (по умолчанию ~600–1200), цикл суперматерика ~600–700 млн; более старое — готовыми древними поясами и кратонами «в замкнутой форме»; (8) режим Generate: быстрая версия без истории за секунды; (9) ископаемые и ледниковый период реализованы.
Следствия для нас: не гнаться за 4,5 млрд лет пошагово — симулировать ~1–1,5 млрд, а древнее задавать готовыми кратонами/поясами; заменить случайные оси на силовую модель; добавить субдукцию и хребтовую кору (в первую очередь для гор у берегов и возраста дна); трещины вести по слабым местам; хранить записи событий отдельно от рельефа.
