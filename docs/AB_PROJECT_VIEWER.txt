New viewer API: setProjectLocked(boolean), getAppliedProgress(), stageProject(scene).
scene = {progress, compose, panes:[{model,frame,pixels},{model,frame,pixels}]}.
Requires two prepared 720x360 frames with angles progress*2/progress*8 and the corresponding A/B model limits. pixels must be full Uint8ClampedArray RGBA and are copied. Models/frames/compose must remain stable after staging.

Lock rejects incomplete geometry or pending history. While locked, viewer start/apply/history/click/export handlers do not start work. The caller MUST separately lock water operations and display controls; water.syncAll can change button appearance and is not a project lock. An already pending PNG callback/native save is not cancelled by this lock.

stageProject only snapshots live viewer state and canvas pixels; it does not run compose, geometry or change the scene. getImageData can fail before any publication. Staging requires readback-capable canvases. It returns synchronous commit()/rollback() for composition with ABProjectSession and a future water transaction.
commit checks lock version, original model/current/generation, composer and applied progress. It adopts exact prepared frame identities, replaces pane models/composer, clears history caches, writes both images, updates applied fraction and slider. It does NOT call start or model.frame. Existing inspection/history/export handlers use adopted pane models/current; next Apply uses the adopted movement value.
rollback before commit only discards. After started/committed publication, rollback restores prior model/current/cache references, composer, fraction, slider, status/inspection texts and both canvas images. Generations stay monotonic to avoid reviving stale jobs. Rollback is idempotent after success and must run before unlock. Canvas/DOM failures during rollback can still propagate; no unconditional rollback guarantee for a broken rendering backend. commit is not self-rolling-back: caller catches failures and calls rollback. Two prepared images are published synchronously; no browser paint between awaited steps is introduced. This is not an OS-level atomic canvas primitive.
