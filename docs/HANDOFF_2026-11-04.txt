2. ЦЕЛЬ И ОГРАНИЧЕНИЯ
Естественная географическая карта: не более 7 материков, сопряжённые берега с объяснимым происхождением, открытый океан и место для крупных морей. Не менять произвольно радиус, возраст планеты или раскладку блоков.

Численное отсутствие sampled конфликтов не доказывает физическую полноту. Нынешний рельеф процедурный, не физическое горообразование. Климат планеты НЕ рассчитан.

5. АКТУАЛЬНЫЕ СОХРАНЁННЫЕ МОДУЛИ И КОНТРАКТЫ
src/equal-area-ab-candidate.js — bounded равноплощадное ядро A/B; src/three-block-prototype.js загружает исходные labels. Геометрия 720x360, история 180x90. Ползунок 0–100% меняет западный эпизод; восточный уже завершён.
src/material-relief-layer.js — старый иллюстративный рельеф, sourceUV обратного переноса и legacy heights.
src/regional-material-terrain.js — create(base, relief), heights(model,frame), materialElevation(u,v). Процедурные крупные формы/пояса и прибрежное ослабление по ИСХОДНОМУ берегу. Новые берега разломов не учитываются. Высоты относительные, не метры.
src/regional-relief-integration.js — build(frame,heights) возвращает {w,h,land,height,east,north,area,neighbors,angularDistance,units}; height воды=NaN, площадь в стерадианах, градиенты относительная высота/радиан; соседство через шов и полюса. createRenderer(models,baseCompose,getMode,regional,legacy) -> {models,compose,field}. field(frame,mode='regional'), modes regional/legacy/material. В legacy высоты прежние, свет уже сферический, не точная старая пиксельная светотень.
Эта интеграция объединяет ранние несохранённые spherical-elevation-field / spherical-relief-renderer прототипы. Их старые архивные filenames НЕ являются зависимостями продукта и не требуют восстановления.
src/spherical-drainage.js — build(field). Сток по наибольшему спуску/угловому расстоянию; ровные участки по BFS; замкнутые минимумы сохранены. Возвращает receiver, terminal, accumulation, basins, network(threshold), stats. receiver=-2 вода, -1 замкнутый минимум, >=0 индекс приёмника. accumulation — площадь водосбора в ср, НЕ расход воды. Водные клетки — общая граница с поверхностью 0, не известные глубины. Basin — последняя сухопутная клетка перед водой или корень замкнутого минимума; тысячи выходов НЕ означают тысячи рек.
src/drainage-overlay.js — createRenderer(render,drainage,getTerrain,getLayer,getThreshold,onSummary) -> {models,compose,data}. data(frame,mode) возвращает drainage. layers terrain/network/basins. Вода/история не перекрашиваются.
src/basin-spill-hierarchy.js — build(field,drainage). Граф минимальных седловин, локальный порог, минимакс-уровень доступа к существующей воде, Kruskal merge forest. localSpillLevel и escapeToWaterLevel РАЗНЫЕ. potentialDepth — гипотетическое заполнение до выхода к воде, не реальная глубина озёр. Ёмкости в relative-height*steradian, не м3. Все текущие водные клетки — общая внешняя граница. Равные пороги имеют технический бинарный порядок, не физическую хронологию.
src/spill-diagnostic-layer.js — createRenderer(render,drain,spill,getTerrain,getLayer,onSummary) -> {models,compose,data}; data -> {field,drainage,hierarchy,summary}. layers terrain/potential/saddles. Эти режимы уже добавлены В существующую src/drainage-candidate.html, не в новую страницу.
src/basin-water-budget.js — LOCAL-only create(field,hierarchy), stage(b,volume), advance(storage,forcing,dt). Ограничен ПЕРВЫМ локальным порогом. Эффективный сток с сухих клеток и прямой дождь на начальную водную поверхность не складываются дважды. Испарение/утечки ограничены водой. pendingSpill — избыток за шаг, не автоматически перенесённый. После объединения бассейнов эту старую advance напрямую применять НЕЛЬЗЯ.
src/basin-water-experiment.js — run(model,{initialStorage?,initialPending?,segments:[{steps,dt,forcing}]}). Накопительный учёт pending, boundary, losses; максимум 4096 шагов. Pending не исчезает между шагами, но не считается пространственно размещённой водой и не испаряется без модели его положения.
src/basin-fill-spill.js — redistribute(field,hierarchy,volumesPerOriginalBasin). Передача избытка по фактическим рёбрам, слияние только если оба бассейна наполнены до общего минимального выхода; сосед с более низким другим выходом не сливается ошибочно. Возвращает pools, poolByBasin, basinStorage, depth, boundaryOutflow, stats. Это мгновенное перераспределение заданного объёма, не скорость течения. Ограничение 200000 операций не повышалось. basinStorage после слияния может превысить старую local capacity.
src/basin-water-resolution.js — resolve(field,hierarchy,snapshot,fillAPI) -> {redistribution,ledger,metadata}. Суммирует storage+pending один раз, прежний boundary не возвращает как воду, новый ledger.pendingTotal=0. Pure function не обеспечивает защиту от повторного воспроизведения одного snapshot сторонним кодом: вызывающий должен заменить живое состояние.
src/coupled-basin-water.js — create(field,hierarchy,fill) -> empty(), advance(state,forcing,dt). Состояние {redistribution,ledger}, совместимо с resolution. P/E/C обязательные scalar/cell arrays, seepage optional0, externalInflow optional по исходным бассейнам. Фиксированный кадр/рельеф: при изменении геометрии создавать новый контекст.
Порядок coupled step: дождь/сток по НАЧАЛЬНОМУ wet mask -> мгновенное перераспределение/слияния -> ставки потерь по POST-INFLOW wet mask, замороженные на шаг -> спад уровня с разделением по MST-порогам, независимые потери после отделения -> финальное перераспределение и баланс. Вход до испарения и фиксированные площади делают метод зависимым от dt. Климат, устойчивые озёра, температура/лёд, грунтовый возврат не рассчитаны. Время не годы, радиус/возраст не меняются.

9. КОНТРАКТ НОВОГО src/coupled-water-ui.js ДЛЯ ВОССТАНОВЛЕНИЯ
UMD global CoupledWaterUI, API:
 create(models,baseCompose,getContext,coupled,fill,doc,win,getVisible,getSurface)
 -> {models:wrapped, compose, attach(view), run(i,kind), reset(i), cancelAll(), refreshAll(), syncAll(), records}
kind wet/dry.
records[i]={token,busy,frame,args,context,state,ticks}; frames WeakMap frame->panel.
wrapped.frame вызывает исходную модель, при720x360 cancel(i,false), сбрасывает контекст/state/ticks/args, регистрирует frame и пишет «Водный эксперимент не запущен».
compose запоминает последние {f,low,h} и поверх baseCompose рисует ТОЛЬКО land-water из завершённого state, если checkbox и regional. Это позволяет refresh сохранять историю, не меняя private paint старого viewer.
refresh проверяет view.panes[i].current.f===args.f и кладёт ImageData текущего compose в canvas.
attach сохраняет view и назначает water-кнопки.
sync блокирует wet при нет current/regional/busy, dry дополнительно при нет state, cancel при !busy, reset при нет ready/state/busy. History/export блокированы при busy/нет ready. При изменении generation чужой history-операцией finally может вызвать sync(i,true), не переопределяя его кнопки.
cancel увеличивает token, снимает busy; по умолчанию ++view.panes[i].generation для отмены старой истории; при onFrame viewer=false, иначе можно отменить собственный draw. Завершённый state не стирает.
run захватывает frame, ++token и ++pane.generation, проверяет актуальность по token/frame/p.current.f/generation. После yield создаёт контекст getContext(frame) -> coupled.create(c.field,c.hierarchy,fill). Считает в ЛОКАЛЬНОЙ state20шагов, каждый с yield/check. Только при valid после20шагов присваивает rec.state/ticks, refresh и статус результата. catch не затирает stale/new state. finally синхронизирует только при совпадении token.
reset отменяет и стирает state/ticks, refresh сохраняет текущую history.
