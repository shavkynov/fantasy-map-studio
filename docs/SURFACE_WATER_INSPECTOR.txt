SurfaceWaterInspector.attach({doc,win,water,view,objects,getField,getSurface,getVisible,isLocked}) requires two panes/records and waterObject0/waterObject1 readout elements. objects is SurfaceWaterObjects. getField must return the regional spherical field registered for the exact detailed frame; integration should use diagnostic.data(frame,'regional').field. isLocked must reflect project-controls busy, not only per-pane water busy.
Returns refreshAll() and idempotent dispose(). Adds click listeners without replacing canvas.onclick, cancelling events or altering existing history inspection. No canvas highlight/overlay/PNG change. Selection is a raster cell associated with exact frame and completed state identities. Client coordinates are converted through the canvas bounding rectangle; nonfinite/outside/right-bottom boundary coordinates are ignored.

Lazy catalog cache: WeakMap(completed state -> WeakMap(frame -> catalog)). Requires immutable completed states/frames; in-place external array mutations are unsupported. No rebuilding on repeated selection of the same snapshot. New frame/state clears selection, even if geometry or numerical contents happen to match. Busy/project lock hides selection details and rejects new selections; cancelled work leaving the same old state can restore the old selection. Material/hidden water shows a hidden-layer message and preserves selection until a real snapshot change. Dry/ocean cells have explicit messages. Card numbers are snapshot-local, not persistent geographical IDs. Units/limits stay those of the catalog; patches are not declared stable lakes/rivers.

Automatic refresh uses MutationObserver on waterBalance0/1 and projectStatus, and change listeners on surfaceMode/waterVisible. These are the current controllers' DOM update points; no polling. Native observer delivery is NOT proven by the fake tests. If MutationObserver is unavailable, caller must explicitly call refreshAll on controller transitions. An integrating page must add the two readouts, load catalog+inspector, retain the project-controls object and pass isLocked:()=>project.busy. The current page does none of this yet. Future integration must verify real water completion/cancel/reset, movement, successful project restore and rollback, and existing history clicks.
