SurfaceWaterInspector.attach now accepts optional highlight:{show(pane,catalog,id),clear(pane)}. Both methods are required when supplied. Existing callers without highlight keep card-only behavior. A single text/render path either supplies the SAME catalog and ID used by the card to show, or clears the layer for no state/frame, no selection, dry/ocean, hidden layer, busy/project lock, catalog/field error and refreshed snapshot invalidation. New frame or completed state clears selection even if values match. Old selection can reappear after cancellation/hiding only if those exact identities survive.

Highlight errors are contained: the card retains its computed information and appends a highlight-unavailable warning; clear is attempted. Readout errors use the same clearing path. Broken clear/drawing backends can still leave pixels; no unconditional recovery guarantee. Inspector.dispose attempts to clear both panes but does NOT dispose the host-owned overlay. Caller must dispose inspector before overlay. No original canvas read/write or export method change in this link.
