WATER STEP TRACE — opt-in controller/replay integration

Baseline for this package: 7a310c40113dbd2a6af62cf8ba5169917dfd238b.
The original helper was saved in that commit. This package wires library paths but DOES NOT activate them on drainage-candidate.html. No page, version, ENGINE, recipe schema, forcing defaults or solver changed. Current .13 has no last-step/runoff display.

HELPER API (unchanged)
WaterStepTrace.create(field) owns copied land/area and private snapshots.
advance(frame,model,before,forcing,dt,combined=false) returns {state,trace}; exactly one actual model.advance. Copies PRE-STEP depth and C; prescribed P before advance or actual combined result atmosphere.precipitation afterwards. Checks effectiveSurfaceInput*dt against water.stepStats.inputTotal and combined acceptedSurfaceInput.
Wet means initialDepth>0. External inflow is unsupported. Trace binds exact frame/result/surface identities; arrays stay private.
diagnose(trace,frame,result,routing,drainage) invokes routing.build on fresh copies and checks effective input rate. Caller must ensure frame, model and drainage come from the same field; identities/dimensions alone do not prove numerical provenance. Do not mutate field neighbors or solver states.

CONTROLLER OPT-IN
Pass extras.trace=WaterStepTrace to CoupledWaterUI.create (or ABProjectWater extras).
Only step 20 is traced; steps 1..19 still call the same model directly. No second advance; avoid copying full arrays for all 20 steps. Each run owns a new local trace context, published only with completed result.
Records have trace/traceContext, null when disabled/empty. lastStep(index) returns {trace,context} or null for busy, stale frame/state or unavailable data. Material/visibility/project-lock display gating still belongs to caller; this is a data accessor, not a new layer.
Dry/Continue replace trace with their actual last step, not current selectors. Cancel and solver errors preserve old completed data. New detailed frame and reset clear it; low history frame does not. Prescribed context is now created locally and committed on success, not published during setup.
If refresh/status throws after result assignment, completed record fields are restored. Canvas/DOM may already be partly changed; NOT atomic renderer rollback.

REPLAY AND PROJECT ADOPTION
Pass deps.trace=WaterStepTrace to ABProjectRecipe.replay. Only its final actual step per nonempty pane is traced. No arrays or context states enter recipe v1; encode/capture stay unchanged.
ABProjectWater.stageProject transfers trace/context, checks pair presence and frame/result/surface/mode identities, and clears missing trace explicitly. Existing record snapshots carry trace references through rollback.
Replay without deps.trace is supported: imported water has trace unavailable until a new run. Empty replay clears it. The adapter trusts replay context factories, as before; it does not cryptographically prove private helper ownership.

ACTIVATION STILL REQUIRED
The page currently passes neither extras.trace nor replay deps.trace. ABProjectControls does not yet forward that optional dependency. Do not claim live .13 integration. A future page/control package must enable BOTH run and replay, supply routing/drainage for the exact frame, and add honest UI/status. Do not relabel catchment area as discharge.
